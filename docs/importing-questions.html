How to import your own questions from JSON

The practice questions on this site live in plain JSON files, one per subject. You can add your own questions by following the same format. The bundled import script validates every question and refuses duplicates, so a bad file cannot break the site.

Where the data lives

PathPurpose
data/bank/<subject>.jsonOne file per subject. This is what a subject page's practice set loads.
data/bank/index.jsonGenerated question counts used by the pages.
data/pool/mixed.jsonMixed pool used on the homepage.
data/pool/ssc-cgl.json and siblingsExam-weighted pools for the four exam pages.
scripts/import_questions.pyValidator and merger. Standard library only.

Question format

Input files are a JSON array of objects. Only five fields matter; extra fields such as id, topic or source are allowed and preserved by the validator's report.

{
  "question": "Which article of the Constitution abolishes untouchability?",
  "options": ["Article 14", "Article 15", "Article 17", "Article 21"],
  "correct_option": 2,
  "explanation": "Article 17 abolishes untouchability and forbids its practice in any form."
}
  • question — at least 12 characters, plain text, no HTML.
  • options — exactly four non-empty strings, all different.
  • correct_option — an integer from 0 to 3, where 0 is the first option.
  • explanation — at least 12 characters. This is what makes the question useful.

Files served to the browser use a compact array form to keep pages fast: ["question", ["a","b","c","d"], 2, "explanation", "optional-id"]. The import script converts your object format into that array form, so you never have to write it by hand.

Import in four steps

  1. Prepare the file. Save your questions as my-questions.json in the object format above.
  2. Validate without changing anything. Run python3 scripts/import_questions.py my-questions.json --subject indian-polity --dry-run. The script reports valid questions, rejected questions with reasons, and duplicates against the existing bank.
  3. Merge. Remove --dry-run to write the merged file into data/bank/indian-polity.json. The script keeps a backup of the previous file.
  4. Refresh counts and publish. Run python3 build_data.py if you use the bundled pipeline, then commit and push. The counts on the pages update from index.json.

Duplicate validation

Duplicates are detected on the normalised question text: lower-cased, punctuation removed and whitespace collapsed. That catches the common case where the same question appears twice with different spacing or a changed question mark. The validator also flags questions whose four options are identical to an existing question, which usually means a re-typed copy with an edited stem.

Nothing is silently dropped: every rejected or skipped question is listed in the report with its index and the reason, so you can fix and re-run.

Keeping your source data safe

Never commit access tokens, private repository URLs or credentials to a public site. If your question bank lives in a private repository, export it to JSON on your own machine, run the validator locally, and commit only the resulting data/bank/*.json files. The site needs no GitHub token at runtime because it is entirely static — the browser only fetches public JSON.
